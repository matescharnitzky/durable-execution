# Change outline

Choose the smallest view that shows reviewers what changed. Use a shallow tree for structure, a short example for a public CLI or data contract, or a sequence for behavior across processes. Use a diff fence to show additions and removals from an existing shape.

For recovery changes, show the normal path and the failure boundary. Label the logical run ID, the native durable store, and the operation that resumes the run. Distinguish framework history from external request logs used as evidence. Keep actual check results in Validation.
